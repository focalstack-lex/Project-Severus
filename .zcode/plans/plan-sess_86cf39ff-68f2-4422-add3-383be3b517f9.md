# Gmail School Updates — Implementation Plan

## Architecture (renderer-first, mirroring your Strava integration)

Your Strava tab already proved the pattern: renderer `fetch` does all HTTP (CSP is null), config lives in localStorage, the Settings tab onboards. Gmail follows it — **no OAuth crates, no HTTP client in Rust**. Rust contributes only two small things: a loopback listener to capture Google's consent redirect (Google killed the paste-the-code flow Strava could use), and Windows Credential Manager storage for tokens.

```
Connect (once): Settings ▸ Gmail → "Connect" → browser consent →
  redirect to http://127.0.0.1:47153 → Rust TcpListener captures code →
  renderer exchanges code+secret for tokens → refresh token → Credential Manager
Polling (every 3 min, paused when window hidden):
  GET messages?q=from:(@your-domain) is:unread  →  metadata headers only
  → diff against seen-ids → new mail → TopHeader badge + Inbox tab + spoken summary
```

**Scope guard:** `gmail.readonly` only — Severus can never send, delete, or move mail. Headers only (From/Subject/Date) — no bodies fetched. Disconnect revokes the token at Google and wipes the keystore entry.

## Your prerequisites (~5 min, before first connect)
1. console.cloud.google.com → enable **Gmail API** on your project.
2. **OAuth consent screen**: External, Testing mode, add your school account as a test user.
3. **Credentials → Create OAuth client ID → Desktop app** → copy the client ID + secret.
4. Know your school domain (e.g. `@davao.cjc.edu.ph`) — it goes in the settings field.

## Rust (`src-tauri`)

**New `gmail_auth.rs`** (~90 lines, `std::net::TcpListener` + `std::thread` — same sync pattern as `watcher.rs`):
- `gmail_begin_auth(client_id, port) -> auth_url` — builds the consent URL (`scope=gmail.readonly`, `redirect_uri=http://127.0.0.1:{port}`, `access_type=offline`, `prompt=consent`) and starts a one-shot listener thread that captures the `code=` (or `error=`) from Google's redirect, replies with a "return to Severus" HTML page, 5-minute deadline. Pure helper `extract_code_from_request(line)` is unit-tested.
- `secure_store(key, value)` / `secure_load(key)` / `secure_delete(key)` — Windows Credential Manager via `keyring` crate (service `"Severus"`). Holds the refresh token + client secret; nothing sensitive in localStorage.
- Register the four commands in `lib.rs`; add `keyring = "3"` to Cargo.toml. No other deps.

## Renderer (`src/`)

**New `lib/gmail.ts`** (mirrors `strava.ts`):
- `GmailConfig { clientId, clientSecret?, domain, pollMinutes, enabled }` in `localStorage["severus_gmail_config"]` (+ `VITE_GMAIL_*` env hydration like AI/ElevenLabs configs).
- `exchangeGmailCode` / `refreshAccessToken` — `fetch` to `oauth2.googleapis.com/token` (access token cached with expiry; 401 → silent refresh).
- `fetchUnreadSchoolMail()` — `GET gmail/v1/users/me/messages?q=from:(@{domain}) is:unread&maxResults=15` then `format=metadata` per message. Diff against `severus_gmail_seen_ids` (capped); new arrivals → `window.dispatchEvent(new CustomEvent("severus:mail-updated", { detail }))` — the exact pattern your Strava stats item already listens to.
- `startGmailPolling()` / `stopGmailPolling()` — interval per config, skips while `document.hidden`; **first sync is a silent baseline** (no announcement spam).

**`AISettingsModal.tsx`** — new "Gmail School Updates" tab (Strava tab structure): client ID, client secret (masked), school domain, poll interval, **Connect** button (begin_auth → `openExternalUrl` → exchange → status), connection state, **Disconnect** (revoke + wipe).

**`TopHeader.tsx`** — a mail pill in the actions cluster (envelope icon + unread count, hidden when disconnected) plus a "School Mail" row in the Status popover (Strava item as template: label + live count + chevron → opens the Inbox tab).

**`ContextInspector.tsx`** — tab union gains `"inbox"`; panel lists recent emails (sender · subject · relative time, refreshed by the `severus:mail-updated` event), click → `openExternalUrl("https://mail.google.com/mail/u/0/#inbox/{id}")`. Gmail stays the reader.

**Voice** — `voiceCommands.ts` Priority-1 block: "check my email / any new emails / school mail" → `onCheckEmail`; App forces a poll and speaks via `speakText(formatReplyWithSir(...))`: "Two new emails, Sir. Latest from the Registrar about enrollment." Announcement phrasing added to `SEVERUS_ECHO_PHRASES` per your echo-suppression convention. Plus `("gmail", "https://mail.google.com")` in the Rust `app_alias` table so "open gmail" works through the existing launch grammar.
