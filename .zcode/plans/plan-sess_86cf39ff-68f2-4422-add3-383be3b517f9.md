# Severus System Control — Tier 1 + Tier 2 Implementation Plan

## Architecture

New Rust module `desktop/src-tauri/src/system_control.rs` — the single source of truth for parsing AND executing OS actions, so voice, the console, and the DeepSeek fallback all go through the same tested, allowlisted path.

**Flow:** spoken/typed text → `system_resolve_command(text)` (deterministic grammar, pure + unit-tested) → if matched: execute (password first when destructive) → if no match: DeepSeek fallback maps freeform text to ONE of the same intents (strict JSON schema in the prompt; execution path identical to grammar hits, so a misparse can never exceed the supported action set).

## Rust (src-tauri)

New `system_control.rs` with:

1. **Intent model** (serde-serializable enum): `LaunchApp(app)`, `OpenKnownFolder(folder)`, `OpenPath(path)`, `VolumeSet(pct)`, `VolumeStep(dir)`, `MuteToggle`, `MediaKey(play_pause|next|prev|stop)`, `ClipboardWrite(text)`, `Screenshot`, `FocusApp(app)`, `ListWindows`, `SnapWindow{target?, left|right|maximize|minimize}`, `MinimizeAll`, `SwitchDesktop(next|prev)`, `LockWorkstation`, `CloseWindow(target)`.

2. **Grammar parser** `parse_command(text) -> Option<SystemIntent>` — normalizes text (lowercase, strips "hey severus/please"), app-alias table (~20 entries: chrome, edge, vscode→code, terminal→wt, explorer, spotify, notepad, calculator, settings, task manager…), known-folder aliases (documents, downloads, desktop, pictures, severus, second brain), verb patterns: "open/launch X", "switch to/focus X", "snap [X] left/right", "maximize/minimize [X] / minimize all", "volume up/down/to N/mute", "play/pause/next/previous track", "screenshot", "next/previous desktop", "lock the pc" (destructive), "close X" (destructive), "list/show windows". Filler-tolerant; returns `Resolution { intent, requires_password }` — `requires_password = true` only for LockWorkstation and CloseWindow.

3. **Executors** (Win32 via the `windows` crate; cfg(windows) guarded like notes.rs):
   - Launch/open: `cmd /C start` (existing pattern in notes.rs:183-198) with alias → exe resolution + PATH fallback
   - Volume: `IAudioEndpointVolume` (COM) for get/set/step/mute
   - Media keys + virtual desktop switch: `SendInput` (VK_MEDIA_*, Ctrl+Win+Left/Right) — keystroke injection is limited to these fixed chords only; no arbitrary typing
   - Windows: `EnumWindows` (+ DWM cloaked check) → `Vec<WindowInfo{hwnd, title, exe}>`; focus via ShowWindow+SetForegroundWindow with the AttachThreadInput foreground lock workaround; snap via monitor work-area + `SetWindowPos`
   - Screenshot: GDI BitBlt of the virtual screen → PNG (`image` crate, png feature) into `Pictures\Severus\`, returns the saved path
   - Clipboard: `arboard` crate (read/write text)
   - Lock: `LockWorkStation()`

4. **Tauri commands** (registered in lib.rs's `generate_handler!`): `system_resolve_command(text)`, `system_execute(intent, confirmed)` (re-checks the password requirement server-side — `confirmed=false` on a destructive intent returns `Err("password confirmation required")` even if the UI is bypassed), `system_list_windows()`.

5. **Cargo.toml**: add `windows` (features: Win32_Foundation, UI_WindowsAndMessaging, UI_Input_KeyboardAndMouse, Media_Audio + Endpoints, System_Com, Graphics_Gdi, Graphics_Dwm, System_Threading), `arboard`, `image` (png only). Exact feature strings verified against the chosen crate version at build time.

## TypeScript (renderer)

- `lib/systemControl.ts`: typed invoke wrappers, `SystemIntent` mirror, password hashing (SHA-256 via `crypto.subtle`, hash-only in `localStorage["severus_control_pw_hash"]`; first destructive action prompts to set it). Threat-model note: this is an accidental-execution gate, not a hardened security boundary — the real gate is Rust's `confirmed` check.
- `lib/ai.ts`: add a slim `chatOnce(config, systemPrompt, userText)` used by the fallback.
- `lib/deepseekIntent.ts`: fallback mapper — strict system prompt ("return only JSON {action, arg} from this list"), response validated against the known intent set before execution; graceful error toast if the model/endpoint is unreachable (never blocks grammar commands).
- `components/SystemConsoleModal.tsx` (Ctrl+Shift+K): input + session history, DeepSeek-fallback spinner state, password set/verify step inline, cheat sheet grouped by category with example phrases, live open-windows list with click-to-focus. Styled with the existing token system (modal chrome, Geist/mono split, SVG icons — Icon.tsx gets `keyboard`, `monitor`, `volume`, `camera`, `lock`, `grid` icons).
- `App.tsx` + `voiceCommands.ts`: new `onSystemCommand(text)` handler invoked from `processCommand` for transcripts the in-app intents don't claim (ordering guard so "close chrome" routes to system while bare "close" keeps closing app views); pending-destructive state wired to the password modal; toast feedback for every outcome; console action added to QuickSwitcher + Status popover.

## Mock harness

`src/dev/mockBackend.ts` gains `system_resolve_command` (small JS mirror for the harness), `system_execute` (canned success), `system_list_windows` (fake windows) so the console UI and password flow remain demonstrable in the browser.

## Scope guards (explicitly out)

No process killing, no arbitrary keystroke/text injection, no sleep/shutdown/restart, no file deletion, no virtual-desktop COM hacks (keyboard-chord emulation only), no Start Menu indexing (curated aliases + `start` fallback).

## Verification (Zero Hallucination Directive)

- `cargo test`: existing 9 tests + new parser suite (~20 cases: every intent, filler words, destructive flags, alias resolution, unknown-command behavior); `cargo build` must pass.
- `tsc && vite build` clean; class-coverage re-check.
- Browser harness pass: console open/execute/password modal/DeepSeek-fallback spinner/window list screenshotted; brand anti-slop rules apply to the new UI (drawn icons, no glow).
- Honest limitation stated up front: real Win32 behavior (volume, snap, focus, screenshot) is verified by cargo test compile + your manual use in the Tauri app — the browser harness exercises UI, mocks the OS layer.
